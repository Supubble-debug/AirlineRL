## 一、可行性结论

工程上有条件可行。保留 Bench2 的 ITSM 业务环境、用户模拟和评分器，新增 ITSM adapter、rollout loop、数据入口与训练入口，复用 AirLineRL 的训练算法，是合理路线。不能仅把 airline 配置改为 itsm。

工程链路跑通与算法效果提升是两个验收目标：前者可以通过接口测试和真实训练 smoke 验证；后者需要冻结数据划分、基线、消融和独立评测，不能提前保证。

主线调整为：Qwen3-8B → 合规示范 SFT → 冻结共同的 SFT 初始化权重 → 独立的 E1–E5 GRPO 实验。SFT 用于学习工具格式、多轮澄清、policy 和执行习惯；GRPO 用于在可靠奖励下进一步优化。该组合对本项目更合适是研究假设，必须通过 base、SFT-only、SFT+GRPO 的同协议对照验证，不能预先声称一定优于纯 GRPO。

前六步不是返工：真实工具、任务时钟、隔离、动作转换、轨迹导出、来源校验和信息边界同时服务 SFT 与 GRPO。新增工作是两套数据准入标准、共同的数据隔离规则，以及 SFT 轨迹与训练阶段。纯 GRPO 可作为以后单独批准的对照，不自动增加本轮训练量。

本地源码已核实：

- `src/agent_rl/trainer/preflight.py` 与 `verl_entry.py` 锁定 airline 协议，需新增 ITSM 路径，保持原 airline 校验有效。
- `Bench2/src/enterprise_worlds/gym/gym_agent.py` 固定生成 `gym_call`；默认跳过 NL 断言；step 的 truncated 固定为 False；后台执行路径未设置任务时钟。
- Gym 的 close/reset 仅有限等待线程，不能据此证明旧 episode 已退出；必须验收取消、超时和资源回收。
- `TauAgentLoop._finalize_episode()` 依赖 tau 的 simulation_run，ITSM 需要真实结构化轨迹导出。
- 现有 rollout 在缺少采样 logprob 时填零。ITSM 训练必须验证真实采样 logprob 的来源，或明确验证训练器如何在正确策略版本下重算所需概率；不能把零值伪装成真实采样记录。
- 上下文轮换会清空此前 response token、mask、logprob 和 turn span。迁移时要明确采用末段训练还是完整分段训练，并记录保留比例，不能声称自动覆盖完整轨迹。
- 本地 tasks.json 共 53 题：31 MSP、22 single；全部包含 gold actions 和 NL assertions。它足以作为工程试点，但任务数量少、存在相似工作流，泛化结论需要谨慎。

## 二、需要补充到原方案的约束

1. 云端运行环境独立验收。核对实际 Python、CUDA、PyTorch、vLLM、verl、Bench2 和 tau2 版本及 GPU；仓库声明 Python 3.12，不能据此假定云端已具备兼容环境。
2. 先确定 episode 协议，再接训练器。任务时间、工具 ID、增量观察、终止原因、错误分类和轨迹导出必须可测试。
3. DB 自由文本比较策略显式配置并记录 effective strategy，防止 llm 静默退回 fuzzy。未计算 NL 时，NL/联合分数记录为未评估，不能当作通过。
4. 同组 G=4 必须对应同一题目、同一策略版本、独立数据库。基础设施失败不能伪装成模型失败参与训练；重试、丢弃或整组重采样策略需要固定，避免凑组或跨版本混组。
5. SFT 与 GRPO 必须使用同一份任务用途登记和家族隔离审计。在 Teacher 采样或学生模型效果调试之前确定任务用途；held-out 不用于生成训练示范、调参、选预算或挑 checkpoint。
6. E1/E2/E3/E4/E5 均从同一份冻结的 SFT 初始化权重独立启动，并重新初始化 RL 优化器/调度器。“按顺序实施”不表示后一个实验继承前一个 RL 权重。base 与 SFT-only 分开保留。
7. 奖励编码的总和守恒不仅检查函数本身，还要检查经过 verl worker 后处理、mask、padding、dtype 及实际奖励处理路径后是否仍成立；若启用 KL 奖励项，需明确它与证据解码的交互。
8. 使用当前二元 outcome 时，GRPO 同组全 0 或全 1 的组内 outcome 优势为 0；KL 等正则项仍可能产生梯度，所以不能简称“完全没有梯度”。验收必须观察有效组比例和奖励驱动的真实参数更新，不能只看进程跑完。
9. 评估同时报告 DB、NL、联合成功率、失败类型、截断、成本和有效组比例。多次评测 seed 不等于增加独立任务数；按任务汇总不确定性，避免夸大统计证据。
10. 迁移本身不自动构成算法创新。论文结论应区分 ITSM 适配工程、算法消融和跨域有效性证据。
11. SFT 不要求唯一参考轨迹或全库精确匹配，但要求每条接纳轨迹在实际可见信息下正确、可执行且符合 policy。不能把“DB=1”“上游验证器全过”或“Teacher 是强模型”单独作为质量证明。
12. SFT 不修复 GRPO reward 的盲区。核心事实错误仍获高分的任务，不能因先做过 SFT 就自动恢复 GRPO 准入；可另行审核为 SFT-only 来源。
13. 原有文本协议保持：训练 DB 文本使用 fuzzy，评测按协议并行报告 fuzzy/LLM 与 NL。D8 跳过 gold 未改变的文本字段，与 fuzzy 对已比较字段的关键事实漏判是两种问题；LLM 裁判的辨别能力须另测，不从 fuzzy 结果推断。

## 三、SFT 与 GRPO 的数据规则

### 3.1 分开准入，共同隔离

| 项目 | GRPO 任务池 | SFT 示范池 |
|---|---|---|
| 学习对象 | 当前策略在环境中的在线轨迹及 reward | 在真实环境中取得、审定合规的目标动作/轨迹 |
| 必要条件 | reward 对正确结果与核心错误有可信区分，执行故障不计模型负分 | 目标行为在该回合可见信息下成立，policy、关键事实和工具结果正确 |
| 是否必须唯一 gold | 不要求唯一动作序列；原则上应接纳所有合法完成方式。现有全库 gold 比对限制须诚实记录 | 不要求唯一序列或唯一最终 DB，可保存多条各自正确的示范 |
| 全库比对 | 沿用已批准的 DB 协议和针对性正反例；盲区不得被隐去 | 可作为诊断，非唯一准入器；用任务目标、关键事实、必需连带操作及未授权写入检查审定 |
| 自由文本 | 关键事实反例漏判的新增题暂不进入此池，不能靠改词迎合 fuzzy | 可通过有依据的事实核验和人工审读接纳正确示范；不把 fuzzy 通过当作内容正确 |
| 上游验证器 | 与本项目任务定义一致的有效检查应通过，同时补齐 policy 差异 | 逐项标记有效、遗漏、冲突；保留有效检查，冲突项须说明并获批，不强求错误验证器通过 |
| 家族/近重复隔离 | 同时对照 SFT、GRPO、dev 和 held-out 的联合用途 | 与 GRPO 一样遵守来源、实体、家族及近重复隔离，不能因为是 SFT 就放宽泄漏门槛 |

可以共用同一批训练任务，但两种用途分别审定，不能把一个总“通过/隔离”标签用于全部用途。可登记为 SFT-only、GRPO-only、both、dev、held-out 或 quarantined。GRPO 资格失败不自动意味着 SFT 合格；历史隔离证据保留。

同一上游任务的多轮改写、不同 Teacher/seed、同义改写、同轨迹拆出的决策样本必须继承同一用途，不能随机按轨迹切到 train/dev/held-out。采样前依据来源和预期工作流保守筛查；取得真实示范后，再按实际动作、必需连带写入和实体重算联合重叠，不能只沿用上游验证器中的记录清单。

SFT 可重新审查的典型来源，是有明确合规示范、但 DB 无法可靠区分某个文本关键事实，或确有多种合法完成方式的任务。以下问题不能因改做 SFT 而忽略：

- prompt 自相矛盾、金额或目标不明：先通过真实用户澄清消除歧义，不能让 Teacher 偷看验证器后猜答案；必要改编另建来源与版本。
- policy 必需操作没有工具：不能把缺失步骤当作成功示范。若改成解释限制、拒绝或明确的部分完成任务，须单独定义目标并批准，不能冒充原任务完成。
- policy 与上游期望冲突：以本项目已批准 policy 为准，记录派生差异，不为通过验证器示范违规操作。
- MSP SLA 规则未定：不能凭“Teacher 认为合理”替用户制定全局业务规则；可澄清的具体选择须记录依据，其余继续隔离。

“约 50 个 SFT prompt 来源”只是待审计估计，不是可用量承诺。按联合隔离重算后再报独立来源、工作流、合格轨迹和有效监督 token 数；同题多采样和拆成多条决策样本不增加独立任务数。

### 3.2 训练并集决定评测是否独立

设 S 为 SFT 使用过的任务及其受隔离规则约束的家族/近重复，R 为 GRPO 的对应集合。S 与 R 可以重叠；dev 和 held-out 必须对照 S∪R 审计。任务没做 GRPO、却用于过 SFT，依然属于训练用途。

不建议把原 dev 与 held-out 合并成一个新的“独立测试集”。dev 已用于调试、预算或选择时，其成绩仅作开发诊断；可以额外汇总 dev+held-out，但必须分别标记，不能用合并分数代替 held-out 主结果。原 dev 也继续遵守不挑 checkpoint 的既定限制。

若要减少训练题、增加评测题，应在任何相关 Teacher 示范生成、SFT、GRPO 或模型效果选择之前，按完整家族和来源规则提出新的用途版本并单独批准；这些预留题及其近重复不能出现在 SFT 池里。已经训练过或参与模型选择的题不能事后改成独立 held-out。v1/v2 保持不变，不默认撤销原划分或挪动原 train 成员；当前推荐先保留原 dev/held-out，增量候选按联合规则处理。

划分结构、来源及 gold 的离线正确性审计不等于使用 held-out 做模型调试。held-out 的 token 测量、模型试跑、Teacher 示范生成和据其表现调整配置仍禁止；最终评测前可做已批准的离线 gold/评分回归。

### 3.3 轨迹质量与学生输入

Teacher 在真实 Bench2 环境中使用统一 policy 与完整工具集合；不得让上游逐题 system prompt 覆盖本项目 policy。策略输入只含当时已经出现的用户信息和真实工具结果；用户模拟器单独持有 persona/known_info，不向 Teacher/学生直接开放整份答案。仅明确标为 SFT-train 的 gold 可作示范制作与审阅参考，不能把私有 gold、断言、task ID 或未来观察拼入学生输入。

每条接纳轨迹都要经过可执行性、动作顺序、身份/权限、用户确认、必需连带操作、关键文本事实、未授权写入及完成声明检查。上游有效验证器是其中一层；抽样人工审读不能替代逐条硬性检查。试点接纳轨迹全部人工审读；规模化后固定分层抽检比例，所有歧义、冲突和自动检查无法定论的样本仍须逐条审读或排除。不能以 Teacher 自评作为唯一质量裁判。

保存原始轨迹、真实工具返回、最终 DB/哈希、Teacher/模拟器版本与采样参数、来源/改编、验证器适用性、审核结论、拒绝理由及成本。拒绝或失败的轨迹不参与 SFT loss；若以后要利用错误恢复轨迹，应另定目标动作与 mask，不自动把错误调用训练为标准答案。

SFT 样本必须复现第 7 步验收过的学生部署输入：同一 policy、94 工具与 done、chat template、thinking 模式、观察序列化、单动作协议及终止规则。不能把上游原生 role/tool 格式直接当作当前 loop 的输入；先核对实际渲染结果。

只对审定的 assistant 动作文本、工具调用参数及相应结束 token 计算 SFT loss；system、用户/模拟器、工具观察、固定问候、padding 为 0。监督标签可以包含已批准训练任务的正确动作，这与把答案放入模型输入不同。检查 label shift、工具 JSON、结束标记与 mask 的 token 对齐。现有 verl 多轮 SFT 数据集只提供候选入口，不能据此宣称已兼容本项目格式。

长度沿用完整观察规则和已验收预算，不静默裁剪工具结果。40,960 仍待验证。若完整轨迹无法装入，可提出按“当前可见历史 → 下一动作”制作样本，但每条输入必须可重建实际历史、只监督目标回合，不以拆分掩盖超长依赖；新格式须单独批准。保留策略推理与 SFT 的长序列显存验证，不能把 SFT 当作长度问题的自动解法。

### 3.4 小规模诊断与对照

在 train 上做 train 能力诊断，dev 单独报告，不能把“36 道 train 的采样”称作 dev 评测。SFT 前、后使用同一批已批准训练任务与同一采样预算做有界诊断，记录每题成功次数、pass@1/pass@k、组内 reward 标准差、混合成功/失败组比例、基础设施失败与截断。pass@k 高不意味着 GRPO 信号足够：全部样本都成功的组同样没有组内 outcome 优势。少量采样未见成功也不证明真实成功率为 0；不要用一次结果设死门槛或立刻丢题。

若 n 次独立同分布的有效采样中有 c 次成功，n≥k 时可报告 pass@k 估计 1−C(n−c,k)/C(n,k)；注明成功判据、n、k、策略版本、温度与模拟器随机性。无效样本的处理按事先固定的规则，禁止只保留成功重试。实际 G 组的混合率应直接报告，不用 pass@k 代替。二元 iid 成功率为 p 时，混合组概率 1−p^G−(1−p)^G 仅作解释，不替代实测。

AirlineRL 正式配置的 batch 30、G=4、total_epochs=75 是参考；其实际全局步数还取决于数据构建与迭代器。新任务数、SFT warm start 和更新次数不同，不能照抄“75”后声称计算量相同。分别冻结 SFT 有效监督 token/步数及 RL episode、有效组、优化步和成本；不为凑到 50 题无限扩题，也不因 SFT 而自动削减 GRPO 池。

至少保留 E0-base（未 SFT 的 Qwen3-8B）、E0-sft（SFT-only 的冻结初始化权重）和 E1（同一 SFT 权重起跑的 outcome GRPO）。E2–E5 使用同一 SFT 数据、预算和初始化，以隔离 RL 组件差异。要声称 SFT+GRPO 优于纯 GRPO，须另批同协议纯 GRPO 对照，并分别报告额外示范、Teacher 和训练成本；仅胜过 base 不能证明 GRPO 的增益。

若启用 KL，提案默认以共同冻结的 SFT 初始化权重作为 RL reference，所有消融保持相同；须在云端确认实际加载权重和 hash，不能悄悄继续指向原始 base。每批实际采样的 behavior/old policy 随训练变化，与 reference 不是同一个角色。SFT 的优化器状态不直接继承给 GRPO。

## 四、给云端 AI agent 的总提示词

将以下提示词发给已连接云端 SSH 工作区的 agent。原方案及本文件需能在云端读取，或直接将内容提供给 agent；本地 D 盘路径不是云端路径。

```text
你是本项目的实现工程师。目标是在现有 AirLineRL 仓库中接入 Bench2 ITSM，
在已完成的 ITSM 适配上，逐步完成 SFT 示范试点、共同 SFT 初始化权重、
E1/E2/E3/E4/E5 的独立 GRPO 实验和冻结评测。

执行环境：用户指定的云端 SSH 工作区。所有安装、测试、模型采样和训练均在云端进行。
不要在本地安装训练依赖或启动训练。不要猜测 SSH 主机或云端项目路径。
若当前会话尚未连接云端，先告知缺少的连接/工作区信息，停止执行。

先读取云端仓库适用的 AGENTS.md、用户提供的迁移方案，以及
docs/itsm_migration_agent_playbook.md（若不存在则使用我在对话中提供的内容）。
方案中的新增接口是设计，不代表当前代码已经实现。所有状态以云端源码和实际输出为准。

【最高优先级的执行规则】
1. 本次仅允许执行用户在当前消息中明确指定的步骤。
   当前迁移会话建议的下一步是 S0，须收到用户明确授权；不重做第 0–6 步。
   阅读本计划或收到“改为 SFT+GRPO”的方向决定，不代表允许采样或训练。
2. 每次最多执行一个编号步骤；该步内部可以完成必要的实现、测试与修复。
3. 完成本步后必须结束本轮，等待我验收。

【实现约束】
- 保留 airline 原有实验协议。优先新增 ITSM 模块，不把 airline 的校验简单放宽。

- gold actions、NL assertions、完整 known_info 等私有字段不得被直接注入策略输入。
  策略只能看到公开政策、工具 schema、用户在对话中提供的信息及真实工具观察。
- gold 可用于评分、离线回归，以及明确登记为 SFT-train 的示范制作和审核。
  SFT 正确动作是监督标签，私有答案不得混入输入；held-out gold 不得用于训练示范。
  不能把 gold 回放或 Teacher 成功当作学生模型能力。
- 所有 episode 独立数据库；任务时钟在实际执行及评分线程一致，并可靠清理。
- 保留真实工具调用、唯一 ID、结构化错误、结果是否收到和终止原因。
- SFT 只监督审定的 assistant 目标动作；GRPO 只训练实际策略生成 token。
  两者的用户/工具/环境观察、固定问候和 padding 均不计算目标 loss。
- 不伪造采样 token 或 logprob；明确上下文截断/轮换后的训练范围。
- 基础设施错误与模型行为错误分开处理，不能静默转成训练 reward=0。
- SFT 和 GRPO 的训练并集与 dev/held-out 按来源、家族和近重复隔离。
  不合并已调试 dev 为独立测试集；不把 SFT 使用过的题移成独立 held-out。
- E1–E5 从共同冻结的 SFT 初始化权重分别起跑，保留 base/SFT-only 对照。
  本轮不自动启动额外纯 GRPO 对照；KL reference 与初始权重另行登记。
- 不覆盖用户已有修改，不读取或输出密钥，不更换系统环境来绕过依赖问题。
```

## 七、方法依据与适用边界

- [DeepSeekMath 原论文](https://arxiv.org/html/2402.03300v3)：包含 SFT 后执行 GRPO 的训练路线及组内相对优势定义；它支持此设计有先例，不证明对 ITSM 必然有效。
- [Hugging Face TRL SFT 官方文档](https://huggingface.co/docs/trl/main/en/sft_trainer)：说明目标序列监督、assistant-only loss 和工具调用数据。仅作方法参考，不要求为本项目安装/切换 TRL；实际入口优先核对仓库固定的 verl 版本。
- [scikit-learn 官方数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)：训练与评测先划分、测试不参与模型选择。本项目额外按 SFT∪GRPO、家族、来源与近重复执行这一原则。
- [HumanEval / pass@k 原论文](https://arxiv.org/abs/2107.03374)：用于解释多采样成功估计；本项目的用户模拟器、依赖工具与训练分组另有随机性，必须报告实际采样设定，不能把公式当作独立性证明。
